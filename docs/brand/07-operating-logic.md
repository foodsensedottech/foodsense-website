# Operating Logic & Decision Principles

## Decision-Making Principles

1. Data before conviction. Build the dashboard before launching the initiative.
2. Phase everything. Test in one store, prove it works, then scale.
3. Simplify or kill it. If it adds more complexity than it solves, it's wrong.
4. Escalate early, not late. Don't wait for a crisis.
5. Ship over polish. Get it out, get feedback, iterate.
6. Tie every initiative to a number. If it can't be quantified, it can't be prioritized.
7. Let market maturity dictate the approach. Adapt to readiness, not templates.

## Standing Rules

- Always send an agenda before any call
- Always confirm scope in writing before work begins
- Always test before scaling (pilot first)
- Always document meeting outcomes as tasks
- Always tie a KPI to every initiative
- Always assign a named owner to every next step
- Always adapt to market maturity level
- Always escalate blockers within one cycle
- Always build the dashboard before launching

## Anti-Patterns (things we never do)

- Overpromise timelines
- Badmouth vendors publicly
- Skip the pilot phase
- Send unreviewed proposals
- Spread teams across too many workstreams
- Present without data
- End meetings without next steps and owners
- Overcomplicate what can be simple

## Stakeholder Map

### Clients
- **Multi-Unit Franchisees:** 10+ locations, need tech strategy across portfolio
- **Multi-Brand Franchise Groups:** Shared infrastructure decisions, portfolio-level thinking
- **Growth-Stage Brands:** 20–200 units, professionalizing their tech stack

### Vendors
- **Technology Vendors:** POS, loyalty, kiosks, delivery, kitchen mgmt, data platforms
- **Integration Partners:** System integrators and dev shops who execute the build

### Partners
- **Advisory & Referral Network (Blackthorn):** Vetted consultants for overflow/specialty work
- **Strategic Advisors:** Senior operators who provide deal flow and introductions
